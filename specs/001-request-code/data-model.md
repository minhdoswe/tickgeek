# Data Model: Email Code Sign-In: Request a Code

Created by Flyway migrations `V1__create_ticket_system.sql` and
`V2__index_outboxes_verification_code_id.sql` (see [research.md](research.md) R15).
All timestamps are `TIMESTAMPTZ`. Emails are always stored normalized (trimmed, lowercase).

## verification_codes

| Column | Type | Rules |
|---|---|---|
| id | bigint identity | PK |
| email | text | NOT NULL, normalized |
| code_hmac | text | NOT NULL; HMAC-SHA256 of `email:code`, hex (R3) |
| status | text | NOT NULL, CHECK in (`PENDING`, `ACTIVE`, `USED`, `INVALIDATED`) |
| attempt_count | integer | NOT NULL DEFAULT 0, CHECK 0–5 |
| request_source | text | NOT NULL; client IP or `unknown` (R6) |
| created_at | timestamptz | NOT NULL DEFAULT now(); request time, used for limits |
| sent_at | timestamptz | NULL |
| expires_at | timestamptz | NULL; CHECK `status <> 'ACTIVE' OR expires_at IS NOT NULL` (R16) |
| used_at | timestamptz | NULL |

Indexes:
- partial UNIQUE `(email) WHERE status IN ('PENDING', 'ACTIVE')`: one live code per email (R4)
- `(email, created_at)`: cooldown and per-email limit
- `(request_source, created_at)`: per-source limit
- `(created_at)`: system-wide limit

State transitions made by the code today:

```text
(new request)                     ──▶ PENDING (expires_at NULL)
PENDING or ACTIVE ──new code requested──▶ INVALIDATED
```

`ACTIVE` and `USED`, and the `sent_at`, `expires_at`, `used_at` and `attempt_count` columns, are
in the schema but not written by any code yet.

## outboxes

| Column | Type | Rules |
|---|---|---|
| id | uuid | PK; UUIDv7 generated by Hibernate on persist (R9) |
| payload | text | NULL allowed; JSON `{"to": …, "code": …}` for a code email |
| created_at | timestamptz | NOT NULL DEFAULT now() |
| published_at | timestamptz | NULL |
| attempts | int | NOT NULL DEFAULT 0 |
| next_attempt_at | timestamptz | NOT NULL DEFAULT now(); set to the request time |
| last_error | text | NULL |
| status | `outbox_status` enum | NOT NULL: `PENDING`, `SENT`, `ERROR`, `CANCELLED` |
| verification_code_id | bigint | NULL, FK → verification_codes.id; set for code emails |

Indexes:
- partial `(verification_code_id) WHERE verification_code_id IS NOT NULL` (V2): serves the
  foreign key check when codes are deleted (R15)

The code request inserts one `PENDING` row per code (R9). No code changes a row after that yet.

## In-process job event (not stored)

| Event | Fields | Meaning |
|---|---|---|
| `OutboxJobScheduled` | `outboxId` (UUID), `delay` (Duration) | "Run this outbox row after the delay", published with delay zero inside the request transaction. Holds no email or code. No listener exists yet. |

## Relationships

```text
verification_codes 1 ──── * outboxes (by verification_code_id)
```

Codes are keyed by email only, so nothing about account existence is needed (R7).

## Configuration values

`application.yaml` (`tickgeek.auth`):

| Key | Default |
|---|---|
| `tickgeek.auth.code-ttl` | 10m (reported as `codeValidMinutes`) |
| `tickgeek.auth.limits.window` | 1h (rolling window of the hourly limits) |
| `tickgeek.auth.limits.resend-cooldown` | 60s |
| `tickgeek.auth.limits.per-email-per-hour` | 5 |
| `tickgeek.auth.limits.per-source-per-hour` | 20 |
| `tickgeek.auth.limits.global-per-hour` | 1000 |
| `tickgeek.auth.code-secret` | `${TICKGEEK_AUTH_CODE_SECRET}`, no default; ≥ 32 bytes |

`application-local.yaml` (the `local` profile, for manual testing only) sets a dev-only
`code-secret` default, `resend-cooldown: 1s` and `per-source-per-hour: 200`.
